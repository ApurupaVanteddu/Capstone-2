# Incident Dataset Profile

## Overview

- **Original source**: [Google Sheets Incident Dataset](https://docs.google.com/spreadsheets/d/1IE8ox8-B9wu6qUZkBIy0i3Iwsvfa0qo7/edit?s=&pli=1&gid=1365699075#gid=1365699075)
- **Local File**: `data/incidents.csv`
- **Total Records**: **2,500** (150 original source records and 2,350 synthetic examples)
- **Columns**: Original source columns, normalized ITSM columns, and `record_source` provenance
- **Domain**: Infrastructure & Media Server Incident Management

Synthetic examples are generated by `scripts/expand_dataset.py` and marked `Synthetic example` in `record_source`. They are varied incident examples for development and retrieval experiments; they are not additional records from the Google Sheets source.

## Category Breakdown

| Category | Incident Count | Typical Symptoms | Resolution Strategy |
| :--- | :--- | :--- | :--- |
| **Storage** | 358 | Capacity alerts, upload failures, archive growth, inode exhaustion | Clean up approved files, review retention, and scale capacity |
| **Application** | 358 | CDN cache misses, API latency, playback and worker failures | Validate application configuration, cache, and worker health |
| **Security** | 358 | Suspicious logins, authentication failures, encoder integrity alerts | Review audit evidence and restore approved identity or software state |
| **Performance** | 357 | CPU and memory pressure, queue growth, request latency | Inspect workload and resource metrics, then tune or scale safely |
| **Database** | 357 | Query timeouts, connection exhaustion, lock waits, replication lag | Review query plans, connection health, and transaction contention |
| **Hardware** | 356 | Controller, memory, interface, cooling, and power alerts | Diagnose device health and follow approved hardware replacement procedures |
| **Network** | 356 | Packet loss, DNS, routing, gateway, and TLS issues | Trace connectivity and coordinate controlled DNS, routing, or policy repairs |

## Schema Normalization

The system indexes the raw columns into standardized ITSM schema:
- `incident_id`: Ticket Identifier (e.g. `INC-5001`)
- `ticket_id`: Support Ticket Reference (e.g. `TKT-1001`)
- `ci_name`: Media Server / Asset Name (e.g. `MediaServer01`)
- `category`: Functional Category (`Storage`, `Application`, `Security`, `Performance`, `Database`, `Hardware`, `Network`)
- `description`: Merged Incident Details & Symptom Description
- `resolution_notes`: Verified Historical Resolution Action
- `priority`: P1 (Critical), P2 (High), P3 (Medium)
- `incident_state`: `Resolved`
- `record_source`: `Original source record` or `Synthetic example`
